# Companion updater operations

Provision signing once as root using `provision-signing.sh`. It stores a Tauri update key plus a durable Android PKCS12 key and password under `/etc/estate-autopilots/secrets`, root owned, directory 0700 and files 0600. It feeds their values to GitHub Actions secrets without printing them. Keep backups under the owner's secret backup policy; losing the desktop private key prevents updating existing apps with that public key. Never replace an existing key just to fix a build.

Embed the returned **public** key with `node apps/desktop/scripts/configure-updater.mjs PUBLIC_FILE`. `UNPROVISIONED` is a deliberate release gate. Public builds must not publish until this is replaced and all three Actions secrets exist.

Public main builds create immutable `companion-vVERSION-SHA` releases. A required final job publishes all signed desktop bundles, Android APK, Chrome downloads/store package, iOS test archives, `latest.json` and `SHA256SUMS.txt`. Only after asset upload succeeds does it advance `companion-test/latest.json`. Stable is a separate manually selected channel; it never advances from a test release. Production `/api/app-updates/CHANNEL/latest.json` relays those fixed GitHub pointers without private credentials or changes to Cloudflare. Get the apps uses the same manifest.

Pip waits until ten minutes after shift start/check-in and until attendance actions and queued work finish. Download failures/tampered signatures never become an install offer. Later quiets the offer for four hours. Changing channel or signing out invalidates late responses. Credentials and offline queues remain in app data. Desktop recovery keeps both prior and failed app directories and blocks re-offering the failed version. An independent previous executable waits for the installer, supervises two startup attempts, and restores the previous app if neither WebView acknowledges startup within 90 seconds.

Recovery currently requires a writable app installation folder. Hosted acceptance must cover the per-user Windows installer and a macOS app copied to a writable Applications folder. Machine-wide MSI/elevated rollback requires further acceptance; do not claim it based on the per-user EXE case.

The new APK signing identity applies from the first updater release onward. Earlier test APKs signed with a different debug key cannot be replaced by this APK; Android refuses mismatched certificates. Preserve their data and record that limitation instead of advising an uninstall. iPhone delivery waits for Apple/TestFlight. The Chrome Web Store ZIP is prepared; listing/approval remains with the owner.

`tools/companion-public/release-sync.py` is the automatic private-to-public bridge. Its user timer checks the existing release-train receipt, requires that identical SHA healthy in production, and exports only a clean checkout of that SHA through the exact client allowlist and secret scanner. It rejects conflicts and never force-pushes. A signing configuration placeholder blocks publication. Install the provided user units and the script only after the updater has passed hosted acceptance and its server routes have shipped through the normal train. The public workflow builds and publishes every resulting main change; the production page reads the channel pointer within a minute. No extra server deployment path is introduced.
